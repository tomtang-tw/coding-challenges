## Detailed Category Feedback

### Core Logic Analysis

The `next()` method in `TeamRotator.ts` is well-designed:

```typescript
next(): Member | null {
    let firstAttempt: Member | null = null;
    let attempts = 0;

    while (attempts < this.members.length) {
        const candidate = this.members[this.currentIndex];
        this.currentIndex = (this.currentIndex + 1) % this.members.length;
        attempts++;

        if (!candidate.isActive) continue;
        if (firstAttempt === null) firstAttempt = candidate;
        if (candidate.id !== this.lastSelectedId) {
            this.lastSelectedId = candidate.id;
            return candidate;
        }
    }

    // Single active member fallback
    if (firstAttempt !== null) {
        this.lastSelectedId = firstAttempt.id;
        return firstAttempt;
    }

    return null; // No active members
}
```

**Key design decision:** The `firstAttempt` variable elegantly handles the single-active-member case. Instead of special-casing it with an `if` check, the algorithm naturally falls through to the fallback after trying all members. This is cleaner than most other submissions' approaches.

**`lastSelectedId` seeding:** The constructor accepts an optional `lastSelectedId` and sets `currentIndex` to that member's position. This allows external state injection, useful for resuming from a previous rotation.

### 💡 Suggestion 3: Implement Deep Copy for Member Immutability

**Current Implementation:**
```typescript
constructor(members: Member[], lastSelectedId?: number | null) {
    this.members = [...members]; // Shallow copy — member objects are shared references
}
```

**Issue:**
The defensive copy only protects against array-level mutations (push/pop). External code can still modify member properties: `originalMembers[0].isActive = false` affects the rotator. The code comment "prevents external mutations" is misleading.

**Recommended Approach:**
```typescript
constructor(members: Member[], lastSelectedId?: number | null) {
    // Deep copy to truly isolate internal state
    this.members = members.map(m => ({ ...m }));
    this.lastSelectedId = lastSelectedId ?? null;
}
```

Or use a `readonly` Member type:
```typescript
export interface Member {
    readonly id: number;
    readonly name: string;
    readonly isActive: boolean;
}
```

**Impact:** Would provide true immutability as claimed in the README.

### 💡 Suggestion 4: Consider Allowing Cyclic `nextN()` Instead of Throwing

**Current Implementation:**
```typescript
if (count > activeCount) {
    throw new Error(`Cannot select ${count} members: only ${activeCount} active members available`);
}
```

**Issue:**
The challenge implies cyclic behavior: `getNext(n=2)` with 4 members returns `[Alice, Bob]`, `[Charlie, Diana]`, `[Alice, Bob]` — cycling. Other submissions allow `nextN(5)` with 3 active members to return `[A, B, C, A, B]`. The error-based approach is valid but potentially unexpected for callers expecting rotation behavior.

**Recommended Approach:**
Offer both behaviors:
```typescript
nextN(count: number, allowRepetition: boolean = false): Member[] {
    if (count <= 0) return [];

    const activeCount = this.members.filter(m => m.isActive).length;
    if (!allowRepetition && count > activeCount) {
        throw new Error(`Cannot select ${count} members: only ${activeCount} active members available`);
    }

    const result: Member[] = [];
    while (result.length < count) {
        const next = this.next();
        if (!next) break;
        result.push(next);
    }
    return result;
}
```

**Impact:** More flexible API that handles both use cases.

/**
 * Iterator Pattern Interface
 * Provides a way to sequentially access team members without exposing the underlying collection
 */
export interface RotationIterator {
  /**
   * Returns the next member in rotation
   * @returns The next active member, or null if no active members available
   */
  next(): Member | null;

  /**
   * Returns the next N members in rotation
   * @param count Number of members to return

  nextN(count: number): Member[];

  /**
   * Checks if there are any active members available
   * @returns true if at least one active member exists
   */
  hasNext(): boolean;

  /**
   * Resets the iterator state (useful for testing)
   */
  reset(): void;
}

### TeamRotator.ts — Core next() Method
```typescript
next(): Member | null {
    let firstAttempt: Member | null = null;
    let attempts = 0;

    // Try to find next active member that isn't the last selected
    while (attempts < this.members.length) {
      const candidate = this.members[this.currentIndex];

      // Move to next index for next call
      this.currentIndex = (this.currentIndex + 1) % this.members.length;
      attempts++;

      // Skip inactive members
      if (!candidate.isActive) {
        continue;
      }

      // Remember the first active member we encounter
      if (firstAttempt === null) {
        firstAttempt = candidate;
      }

      // If this member wasn't just selected, return it
      if (candidate.id !== this.lastSelectedId) {
        this.lastSelectedId = candidate.id;
        return candidate;
      }
    }

    // If we've gone through all members and only found the last selected one,
    // return it anyway (edge case: only one active member)
    if (firstAttempt !== null) {
      this.lastSelectedId = firstAttempt.id;
      return firstAttempt;
    }

    // No active members found
    return null;
  }
```
